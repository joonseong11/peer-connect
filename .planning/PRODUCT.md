# Peer Connect — Product Vision & Roadmap

> 이 문서는 Peer Connect의 철학, 현재 상태, 문제 진단, 해결 방향을 담고 있습니다.
> 에이전트는 이 문서를 기준으로 프로덕트 개선 작업을 자율적으로 판단하고 실행합니다.
> 최종 업데이트: 2026-03-18

---

## 1. 철학과 비전

### 한 줄 정의

**"신뢰 기반 개발자 네트워크 — 함께 일한 동료가 증명하는 커리어 포트폴리오"**

### 핵심 가치

| 가치 | 설명 |
|------|------|
| **신뢰 우선** | 초대제를 통해 실제로 함께 일한 사람들만 연결. 형식적 네트워킹이 아닌 실질적 신뢰. |
| **동료 증명** | 자기 PR이 아니라 동료의 추천서로 역량이 증명됨. 제3자 검증. |
| **깊은 연결** | 팔로워 수가 아닌, 서로의 맥락을 이해하는 관계. |
| **커리어 자산** | 추천서와 프로필이 시간이 지날수록 가치 있는 포트폴리오가 됨. |

### 신뢰 레이어 모델

```
초대 (Trust Gate) → 프로필 (Context) → 추천서 (Social Proof) → 모임 (Real Connection)
```

각 단계가 신뢰를 축적하며, 이 축적된 신뢰가 외부에서도 가치를 가지는 것이 목표.

### LinkedIn과의 차별점

| LinkedIn | Peer Connect |
|----------|-------------|
| 아는 사이 아닌 사람도 추천 가능 | 초대 기반 → 실제로 함께 일한 사람만 |
| 추천이 형식적 (스킬 +1) | 실제 경험 기반 상세 추천서 |
| 프로필이 자기PR | 동료가 증명하는 신뢰 |
| 누구나 가입 | 검증된 네트워크 |
| 글로벌, 범용 | 한국 개발자 특화, 밀도 높은 커뮤니티 |

## 2. 현재 상태 (2026-03-18)

### 지표

- **멤버**: ~30명 (전원 창업자의 지인)
- **추천서**: ~28개 (거의 포화 — 1인당 1회 제한)
- **모임(Gathering)**: 활동 없음
- **재방문율**: 거의 0 (활동이 일어나지 않고 있음)

### 구현된 기능

- [x] Google OAuth 로그인
- [x] 초대제 (2슬롯, 코드 기반)
- [x] 프로필 작성/수정 (이름, 역할, 소개, 커리어, 연락처, 사진)
- [x] 동료 추천서 작성/삭제 (1인 1회, 20자 이상)
- [x] 멤버 디렉토리 (로그인 필요)
- [x] GitHub 배지 (동적 SVG, 마크다운 복사)
- [x] 외부 추천서 클레임 (비회원에게 추천서 링크 공유)
- [x] 모임(Gathering) 게시판 + 댓글
- [x] 이메일 알림 (추천서, 댓글, 일일 다이제스트)
- [x] 계정 설정/삭제

### 기술 스택

- SvelteKit (SSR)
- Supabase (Auth, DB, Storage)
- Tailwind CSS
- Resend (이메일)
- Vercel (배포)

## 3. 문제 진단

### 3.1 재방문할 이유가 없다

- 30명은 이미 서로를 알고 있음
- 새 콘텐츠(추천서, 모임)가 생기지 않음
- 피드/타임라인이 없어 "지금 들어가야 할 이유"가 부재

### 3.2 추천서 생태계 포화

- 1인 1회 제한 → 28/30 이미 거의 전원이 작성
- 더 쓸 추천서가 없음 → 핵심 기능이 정체

### 3.3 초대할 동기가 약하다

- "초대하면 나에게 뭐가 좋은데?"에 대한 답이 불명확
- 초대해도 플랫폼 안에서 할 게 없으면 민폐

### 3.4 외부에서 가치가 보이지 않는다

- 멤버 프로필이 로그인 뒤에 숨어있음
- 추천서의 가치가 플랫폼 안에 갇혀있음
- "이게 왜 필요한데?"에 대한 외부 답변 부재

### 3.5 소규모에서 "플랫폼"이 부자연스럽다

- 30명 규모에서 모임 게시판은 카톡보다 불편
- 플랫폼 기능보다 관계가 먼저인 규모

## 4. 해결 로드맵

### Phase 1 — 외부 가치 만들기 (최우선)

> 목표: "Peer Connect에 추천서가 있으면 이직/채용에 유리하다"는 인식 만들기

| # | 작업 | 상세 | 영향도 |
|---|------|------|--------|
| 1.1 | **공개 프로필 페이지** | `/members/[id]`를 비로그인으로도 열람 가능하게. 추천서, 프로필 정보가 외부에서 보여야 함. OG 메타태그, SEO 최적화 포함. | 높음 |
| 1.2 | **추천서 다회 허용** | 1인 1회 → 프로젝트/시기별 복수 추천서 허용. "2024 A프로젝트 협업" 같은 맥락 태그 추가. | 높음 |
| 1.3 | **경량 embed 위젯** | 개인 블로그/포트폴리오에 추천서를 embed할 수 있는 `<iframe>` 또는 JS 위젯. shields.io 스타일 작은 뱃지도. | 중간 |
| 1.4 | **추천서 PDF/이미지 export** | 이력서에 첨부할 수 있는 추천서 요약 PDF 또는 이미지 다운로드. | 중간 |

### Phase 2 — 재방문 이유 만들기

> 목표: 기존 멤버가 주 1회 이상 자연스럽게 방문

| # | 작업 | 상세 | 영향도 |
|---|------|------|--------|
| 2.1 | **위클리 다이제스트 이메일** | 새 멤버, 새 추천서, 새 모임 요약. 현재 일일 다이제스트를 위클리로 전환/보강. | 높음 |
| 2.2 | **추천서 작성 리마인더** | "아직 추천서를 쓰지 않은 동료가 3명 있어요" 같은 넛지 알림. | 중간 |
| 2.3 | **커피챗 랜덤 매칭** | 월 1회 자동으로 두 멤버를 매칭. 이메일로 소개. 소규모에서 효과적. | 중간 |
| 2.4 | **프로필 업데이트 피드** | 홈에서 "최근 프로필 업데이트한 멤버" 보여주기 (현재 부분 구현). | 낮음 |

### Phase 3 — 성장 엔진

> 목표: 100명 → 500명으로 자연 성장하는 구조

| # | 작업 | 상세 | 영향도 |
|---|------|------|--------|
| 3.1 | **공개 프로필 SEO** | 구글에서 "홍길동 개발자"로 검색하면 Peer Connect 프로필이 뜨도록. sitemap, structured data. | 높음 |
| 3.2 | **초대 시 상호 추천 강화** | A가 B를 초대 → B 가입 → A에게 추천서 쓰기 유도 + B도 A에게 쓰기 유도. 양방향 추천 플로우. | 높음 |
| 3.3 | **신뢰 네트워크 시각화** | 나를 중심으로 한 초대/추천 관계 그래프. 초대할수록 네트워크가 시각적으로 풍성해짐. | 중간 |
| 3.4 | **초대 슬롯 확장 인센티브** | 추천서 3개 이상 받으면 초대 슬롯 +1 같은 보상 구조. | 낮음 |

## 5. 구현 가이드라인

### 에이전트 자율 판단 기준

이 문서를 참조하는 에이전트는 다음 기준으로 작업을 판단합니다:

1. **Phase 순서를 존중**: Phase 1 → 2 → 3 순서대로. 단, Phase 내 항목은 독립적이면 병렬 가능.
2. **작은 단위로 배포**: 각 항목은 독립적으로 배포 가능한 단위로 구현. 하나의 거대한 PR이 아닌 작은 PR들.
3. **기존 디자인 시스템 유지**: Tailwind + 현재 컬러 시스템 (`peer-*` 토큰) 사용. 새 디자인 라이브러리 도입 금지.
4. **한국어 우선**: 모든 UI 텍스트는 한국어. 코드 주석/변수명은 영어.
5. **Supabase 마이그레이션**: DB 스키마 변경 시 반드시 마이그레이션 파일 생성.
6. **테스트**: 핵심 로직(서버 함수, API 엔드포인트)은 테스트 작성. UI는 수동 검증.
7. **보수적 변경**: 기존 기능을 깨뜨리지 않도록. 특히 인증, 초대, 추천서 플로우.

### 의사결정 우선순위

```
사용자 가치 > 성장 > 기술적 완성도 > 코드 품질
```

- "이 변경이 멤버에게 즉시 가치를 주는가?"가 최우선 질문
- 완벽한 코드보다 빠른 가치 전달이 중요
- 단, 보안(인증, 권한)은 절대 타협하지 않음

### 브랜치 전략

- `master`: 프로덕션 (Vercel 자동 배포)
- `develop`: 개발/스테이징 (Vercel preview)
- Feature 브랜치: `feat/[phase]-[item]` (예: `feat/1.1-public-profile`)
